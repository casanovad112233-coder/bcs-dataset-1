# Project Memory

Operational memory for the BCS question-bank repo (uttoron.academy scrapes -> pipeline -> JSON).

## Pipeline workflow

1. `python scrape_questions.py` scrapes HTML from `links_to_scrape.md`, one page at a time, via Firecrawl (skip existing files).
2. `python -m pipeline <stem>_bcs.html` parses HTML -> JSON + report. It is deterministic; no LLM is called. Unfinished bits (classifications / answers / solve notes) are listed in the report and filled from `output/<stem>_*.json` files on rerun.

## Scraping gotchas

- Firecrawl free plan: ~11 req/min. Use `--delay 6` and retry logic; 429s appear mid-batch.
- 41st & 37th come back as empty shells (54 bytes) from Firecrawl; fall back to plain `curl`. Their `<img src>` paths are root-relative (`/media/...`); the pipeline resolves them against `https://uttoron.academy`.
- Some pages have a 200-question layout; early exams (10th-14th, etc.) have 100, 19th has 50. 17th was long listed as 70 (old scrape 234KB) but live source now shows 100 (verified 2026-08-31 via direct HTML fetch: 363KB, 100 .single-question blocks). Always trust the parse count, not a fixed 200.

## Pipeline fixes applied

- `pipeline/images.py`: resolve root-relative / relative image `src` against `BASE_URL`.
- `pipeline/extract.py`: images are renumbered with a single per-question index sequence spanning question scope first, then solve scope. A question image and a solve image must never share the same `q<N>_img<k>` filename (the later write used to overwrite the earlier one). Example: q173 question = `q173_img1.png`, solve = `q173_img2.png`.
- `pipeline/validate.py`: empty `question` text is OK for image-only questions, but only if `question_image_paths` is non-empty. Errors if empty with no question image, or with an image only in the solve note.
- `pipeline/report.py`: "Image questions (verify manually)" section lists image-only questions with their question/solve paths.

## Equation extraction caveat

- Some pages (e.g. 49th) render math as MathJax spans (`MJXp-mfrac`, `MJXp-msubsup`, etc.). `pipeline/common.py` now converts them: fractions -> `n/d`, superscripts -> unicode (`x^2` -> `x²`, works for Bengali digits too), subscripts -> `log_x` / `log₁₀`. A space is inserted between an integer and a following fraction (mixed numbers: `৭ ১/২`, not `৭১/২`).
- Some pages (e.g. 12nd/20th/27th/30th/33rd/34th/46th/47th) render math TWICE: an `MJXp-math` preview AND a `MathJax_SVG`. The SVG is skipped when an MJXp preview exists (dedup); it is only read (via `<text>` nodes) when it is the sole rendering. Without this, options duplicated e.g. `১২১/২%১২১২`.
- Other pages (e.g. 48th) carry raw LaTeX text (`\(\mathrm {x+\frac{1}{x}}\)`) — `pipeline/common.py` `latex_to_text()` now converts it to readable equations: `\frac`/`{a \over b}` -> `a/b`, `\sqrt{x}` -> `√x` (parenthesized when the radicand has operators), `^`/`_` scripts -> unicode super/subscripts (works for Bengali digits), `\mathrm`/`\underline` unwrapped, `\space`/`\ ` -> space, `\times`->`×`, `\therefore`->`∴`, `\circ`->`°`, `\le/\ge`->`≤/≥`, `\log` kept literal, `\left/\right/\Big` delimiters kept. Only `^`/`_` followed by `{`, a digit, or `+/-` are treated as scripts (so prose underscores like `76−80_ On` survive). Wired into `clean_html_to_text`, so regeneration produces converted text directly. 24 exams were regenerated (10th,11st,13rd-18th,22nd-24th,28th,31st,32nd,37th-45th,48th) to apply this; 50th keeps its manual JSON fix (no HTML data).
- Even with the converter, still spot-check the source HTML for wrong exponents in the *source itself* (e.g. 49th q18 LCM first term was written `4x²`, intended `4x³`).
